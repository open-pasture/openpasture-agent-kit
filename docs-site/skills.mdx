# Skills

Skills are portable operating procedures. They teach an agent how to work through
farm jobs without tying that knowledge to one runtime.

The kit discovers skills from `skills/*/SKILL.md`. Connectors can list and read
those files so an agent can load the runbook it needs.

## Current Skills

- `daily-grazing-decision`: run one decision for one herd. Assemble context,
  read signals, consult knowledge, decide, write reasoning a farmer trusts,
  submit, handle the farmer's response, confirm the boundary, and evaluate the
  outcome.
- `morning-brief`: turn the latest decisions into a plain-language daily
  summary.
- `rotation-planning`: sequence paddocks over the coming weeks against rest,
  recovery, and the forecast.
- `pasture-assessment`: read forage, residual, and recovery from field notes,
  imagery, and collar pressure.
- `farm-onboarding`: create the first farm, paddocks, and herd, link collars,
  and set autonomy.
- `geo-onboarding`: turn map screenshots and sketches into draft farm and
  paddock geometry.
- `knowledge-ingestion`: add trusted sources Alexandria does not carry as
  cited lessons.
- `data-pipeline-setup`: connect another vendor's web app as a recurring
  observation source.
- `pipeline-spypoint`: example vendor pipeline skill.

## Use Skills From The CLI

```bash
openpasture skills list
openpasture skills show daily-grazing-decision
```

## Writing A Skill

A good Openpasture skill should:

- keep the farmer's decision authority visible,
- act only within the herd's autonomy setting, and say what was sent and
  whether it was confirmed,
- ask for the most useful missing observation instead of guessing,
- name the tool calls it expects the agent to use,
- explain how to check the result,
- stay useful across CLI, MCP, Hermes, and future connectors.

Skills are curriculum. Tool handlers are execution.

Source files: `skills/` and `src/openpasture/skills.py`.
