# Knowledge

Openpasture should not lean only on generic model priors. It reasons with
lessons from trusted practitioners and research, and connects them to the
condition of a specific farm on a specific day.

## Sources

- **Alexandria** is the primary source. It carries research papers,
  practitioner videos, and hands-on grazing wisdom from graziers like Greg
  Judy. The engine queries it for the situation at hand.
- **The curated local corpus** in `knowledge.db`, starting from `seed/`. It
  holds distilled lessons with stable ids and attribution, plus sources the
  farmer adds.

The curated corpus still matters. Decisions cite lessons by
`knowledge_entry_id`, and those ids should stay readable years later. The seed
also keeps decisions grounded when Alexandria is not configured or cannot be
reached.

## Entry Types

Every curated lesson is a `KnowledgeEntry`:

- `principle`: a durable rule of thumb,
- `technique`: a repeatable management move,
- `signal`: something observable that changes interpretation,
- `mistake`: a known anti-pattern or warning sign.

## Retrieval

During a decision, the agent searches for the situation at hand, such as
residual before heavy rain or rest in a summer slump, not the whole corpus.
Lessons that shaped the call are recorded on the decision. Generic wisdom with
no link to the situation should not be cited.

```bash
openpasture knowledge search "leaving residual before rain" --limit 5
```

## Adding Sources

Search first. Ingest only what Alexandria does not already carry: the farmer's
own notes, local extension material, or trusted sources not yet indexed. The
`knowledge-ingestion` skill walks through it.

## Seed Knowledge

On first run, the local knowledge store loads the seed when the knowledge
database is empty.

```bash
export OPENPASTURE_LOAD_SEED=0 # skip auto-load
export OPENPASTURE_LOAD_SEED=1 # force reload
```

## Releases

- `farm.db` holds the farm's own data, including the decision record.
- `knowledge.db` holds the shared curated lessons.
- Knowledge releases can be versioned and updated without touching farm data.
- Lesson ids cited by past decisions should keep resolving after an update.
